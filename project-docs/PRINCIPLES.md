# 원칙과 역할 경계

## 배경
PentAnalyst의 AI(Gemini)는 그라운딩이 제한적이라(유료 키에서만 가능) 분석이 얕다. 그래서 Claude 아티팩트 "주식 데스크"를 만들었다. 데스크는 앱을 대체하는 게 아니라 **앱이 못 하는 부분만** 맡는다. 데스크가 필요 이상으로 복잡해져 앱의 역할을 침범하면 초점이 흐려진다.

## 역할
| | PentAnalyst (앱) | 주식 데스크 (Claude) |
|---|---|---|
| 데이터 수집 | 전부 (Worker: Yahoo/Stooq/Finnhub/FRED 등) | 하지 않음. 앱 데이터를 받아 쓴다 |
| 지표·점수·규칙 판정 | 전부 (단일 소유) | 하지 않음 |
| 차트 렌더링·표시 | 전부 | 최소한 (필요 시 이미지 해석용 뷰) |
| 웹 리서치 | 하지 않음 | 한다 (실적일, 뉴스, 가이던스, 이벤트) |
| 비정형 정보 해석 | 하지 않음 | 한다 |
| 서술형 종합 판단·반론 | 하지 않음 | 한다 (규칙 점수를 읽고 보강/반박) |
| 차트 이미지 해석 | 하지 않음 | 한다 |
| 개인 데이터(메모·수량·진입가) | 보관 | 필요 없으면 받지 않음 |

## 판별 질문 (새 기능을 어디에 둘지)
1. 코드로 결정론적으로 짤 수 있는가? → **앱**.
2. 웹 검색·문서 이해·서술적 추론이 필요한가? → **데스크**.
3. 두 앱 모두에 있어야 하는가? → 대개 설계 오류. 한쪽이 소유하고 다른 쪽은 읽기만 한다.

## 표시 원칙
- 규칙 점수와 Claude의 판단은 UI에서 **다른 라벨**로 분리한다. (규칙 점수를 "Claude 판정"이라 부르지 않는다.)
- 공식에서 나온 숫자를 확률처럼 보이게 하지 않는다.
- 외부(브릿지) 파일은 표시 전용이며 항상 이스케이프한다.

## 하지 않는 것
- 프레임워크 도입·전면 재작성 (앱은 단일 파일 No-Build PWA 유지).
- 모듈별 개별 Drive 동기화 신설 (GSYNC 하나로).
- 데스크에 지표 엔진·차트 엔진·저널을 새로 만들거나 확장.
